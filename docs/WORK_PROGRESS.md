## Подтверждённые особенности и ошибки Pro

- Текущие тарифы сохраняются асинхронно; сообщение об успехе выводится до завершения Room. Даты последнего сохранения нет.
- Инициализация формы тарифов получает начальный null от collectAsState и помечает форму initialized до прихода сохранённых ставок: возможна пустая форма при существующих тарифах.
- Резервная копия в профиле — заглушка.
- Авансы и штрафы на главной — постоянные нули; отдельной таблицы и CRUD нет.
- Ввод показателей нового и редактируемого дня использует toDoubleOrNull без нормализации запятой. Тарифы нормализуют запятую, что создаёт разные правила ввода.
- Новый день: SimpleDateFormat.parse не проверяет полное совпадение с исходной строкой даты.
- Даты вахт имеют dd.MM.yyyy, рабочие дни — yyyy-MM-dd. Копия должна сохранять оба действующих формата без переписывания истории.
- Создание вахты: проверка getActiveShift и insertShift не составляют единую транзакцию.
- DAO назначает shiftId без проверки существования вахты; внешнего ключа нет.
- Даты связанных дней не сверяются с границами вахты.
- ShiftScreen использует java.time при minSdk 23 без coreLibraryDesugaring: риск несовместимости Android 6–7.
- В форме изменения дат вахт применяется SMART-разбор DateTimeFormatter: требуется строгая проверка.
- Форма добавления дня открывается через лишнее подтверждение.
- CI исходно выполняет только assembleDebug, без unit-тестов и lint.

Уже исправно в исходной Pro, сохранить:
- Ставки хранятся в WorkDayEntity, редактирование копирует день и сохраняет эти ставки.
- Пустые показатели представлены null; WorkHistoryScreen скрывает их отдельно для каждого показателя.
- deleteShiftSafely сохраняет дни и снимает привязку в транзакции; в интерфейсе уже есть предупреждение и число дней.
- Переназначение дня в другую вахту уже предусмотрено; отображаемая нумерация отделена от ID.
- Постоянный ключ подписи подключён через существующие GitHub Secrets.
